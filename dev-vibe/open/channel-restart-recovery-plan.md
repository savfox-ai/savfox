# Channel 重启恢复与多实例隔离方案

## 1. 目标

Savfox 进程停止并重新启动后，每个已保存且启用的 Channel 实例都应独立恢复。一个实例的配置错误、认证失败或重试不得阻止 Gateway 与其他实例启动，也不得借用同类型其他实例的配置或状态。

本方案把 Channel 的三个概念严格分开：

- **类型**：Discord、Telegram、Arkret 等配置模板与协议实现。
- **实例**：具有不可变 `id` 的独立配置、运行时和状态主体。
- **名称**：可编辑的显示标签，不参与运行时寻址。

## 2. 当前启动机制

Gateway 启动时读取 `channels/*.json`，遍历所有 `enabled = true` 的配置并按类型启动。单个实例启动失败会记录日志，Gateway 仍继续启动其他实例。

这保证了基础的故障隔离，但“启动函数返回成功”不一定等于外部连接已经认证并可收发消息。Arkret 等带后台重试的 Channel 必须继续暴露实例级运行阶段和最后错误。

## 3. 真实风险、解决方案与优先级

| 优先级 | 风险 | 影响 | 解决方案 | 状态 |
|---|---|---|---|---|
| P0 | Arkret 重绑校验扫描所有 Arkret 配置 | 不同实例不能绑定各自 Agent | 校验只检查请求携带的准确实例 ID；新增时仅按准确名称匹配潜在同一实例 | 已完成 |
| P0 | 保存 Arkret 后按类型启动 | 修改一个实例可能启动/影响全部 Arkret 实例 | 停止并重新启动保存结果中的准确实例 ID | 已完成 |
| P0 | Channel ID 随名称重新生成 | 改名后监听器、Applet 和 Arkret 加密状态路径失配 | 仅创建时生成 ID；已有合法实例 ID 永久保留，名称与 slug 可修改 | 已完成 |
| P0 | “已配对”被展示成“Active” | 后台认证失败或重试时仍给出正常工作的假象 | 分离 `pairing_state` 与 `runtime_phase`；卡片显示 Paired、Starting、Listening、Retrying、Stopped 和最后错误 | 已完成 |
| P1 | DingTalk 启动每个实例时先读取类型级首个配置 | 多个 DingTalk 实例可能全部使用同一凭据 | 只从当前循环的 `ChannelConfig` 解析；删除启动路径中的类型级回退加载 | 待处理 |
| P1 | 启动结果只有聚合日志，没有可查询实例报告 | 重启后难以判断哪些实例未恢复 | 保存实例级启动状态：disabled、starting、ready、retrying、failed，并在 `channels.status`/健康页展示 | 待处理 |
| P1 | 部分 Channel 是 Webhook 模式，状态却可能等同于 Connected | UI 把“路由已配置”误认为外部连接在线 | 统一状态语义：Configured、Listening、Connected、Degraded；Webhook 只显示 Ready/Configured | 待处理 |
| P1 | 未实现持久连接的类型在启动时仅写日志并跳过 | 用户可能不知道该实例不会主动工作 | 建立类型能力矩阵；保存时校验模式，状态接口明确返回 `unsupported_runtime` | 待处理 |
| P2 | 缺少完整的停止—启动恢复集成测试 | 回归只能由真实账号人工发现 | 使用临时配置目录与假传输层测试多实例枚举、独立失败、准确恢复和状态报告 | 待处理 |
| P2 | 进程硬退出不能验证清理路径 | 重启时可能残留端口、锁或子任务问题 | 增加优雅关闭测试；Windows 上验证监听端口与子进程退出，再启动同一配置 | 待处理 |

## 4. 全站处理原则

1. 所有读取、保存、测试、启停、解绑、删除和状态查询都以不可变实例 ID 为目标。
2. 名称仅用于展示，允许重名但新建界面应默认生成不冲突的名称。
3. 类型级动作必须显式标注“全部实例”；普通实例操作不得退化为类型级广播。
4. `configured` 只表示配置可解析；`ready/connected` 必须来自真实运行时。
5. 后台重试任务必须暴露阶段、尝试次数、最后错误与更新时间。
6. 单实例失败不阻止 Gateway 和其他实例启动，但必须在 UI 和状态接口中可见。
7. 危险操作只清理目标实例的运行时和持久状态。
8. 启动恢复应幂等：同一实例重复启动不得产生重复监听器。

## 6. Arkret 验收标准

1. 两个 Arkret 实例可分别绑定不同 Agent。
2. 保存、断开或重绑一个实例不启动、停止或修改另一个实例。
3. 修改 Channel 名称后实例 ID、监听器键、Applet 注册键和 Arkret 本地状态归属不变。
4. 已完成授权但监听器未认证时显示 `Paired` 与 `Retrying/Needs attention`，不得显示 Connected。
5. 只有监听器处于订阅或派发阶段时，实例状态才是运行/连接。
6. 重启 Gateway 后，每个启用且配置完整的 Arkret 实例都会单独创建监听器；失败实例保留重试诊断。

## 7. 验证策略

自动测试不连接用户的真实 Discord、Telegram、Arkret 或其他外部账号。代码级测试覆盖配置枚举、实例选择、ID 稳定性和状态映射；真实重启验收应在可控测试账号或假服务上执行，并记录每个实例的启动阶段和最后错误。
