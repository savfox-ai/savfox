# 渠道执行可靠性

Gateway 同时最多接纳 128 个渠道任务，包括排队和执行中的任务；整个进程最多并行执行 16 个，同一会话最多并行执行两个。每个会话收件箱最多保存 32 条等待消息。接纳任务时不会持有协调器注册表锁等待队列空间。预算耗尽时拒绝接纳，具有持久化收件箱的来源应保留事件并重试。协调器在执行任务和队列均为空时立即退出，退出与接纳使用同一把锁；退出边界上已经接纳的消息仍会处理。注册表还设置了最多 128 个协调器的硬上限，已完成会话不会积累长期驻留的空闲任务。

原生 Agent 调用的执行期限为 120 秒。相关联的工具审批将期限延长到 180 秒，收到决定后恢复正常期限。超时、提供商错误和事件流错误均返回失败，即使此前已经输出部分文本，也不会将截断文本报告为完整回答。清理只中断本次提交的 turn，旧调用的超时不会中断持久会话上后续的 turn。临时会话及并发 fork 的会话在成功和失败后都会关闭并移除；持久会话可继续用于后续调用。

支持编辑消息的渠道只有在完整最终版本得到确认后才视为发送成功。最终编辑失败时，流式写入器使用原消息最多尝试三次；仍然失败时，转入普通最终消息的重试发送流程。编辑 API 的 HTTP 错误和业务错误会参与判断；仅初始片段发送成功不代表完整回答已送达。

渠道响应长度限制作用于最终消息，包括分页编号、重叠上下文和重复代码围栏。必要时缩减重叠长度，为新正文保留空间；代码围栏边界不重复上下文。自定义上限极小时，如果编号与正文无法同时容纳，则省略编号。代码切分保留正文空行及末尾换行。

## 会话持久化与资源生命周期

网关会话元数据保存在 Savfox home 下的 `gateway-session-store.sqlite`。首次成功打开时，以事务导入旧的 `gateway-session-store.json`，并保留旧快照原样。之后普通更新只修改一个会话行；UI 更新只有在持久化成功后才确认。批量路由迁移和清理仍使用事务。已删除 ID 保留墓碑，因此 rollout 文件删除失败也不会在缓存刷新时恢复已删除会话。

备份请使用 SQLite 在线备份 API，或先停止网关，再一起复制数据库及可能存在的 `-wal`、`-shm` 文件。旧 JSON 仅是迁移输入，不是最新备份；降级到只读取 JSON 的版本前需要明确导出。SQLite 文件保存权威元数据，不能作为可重建缓存直接删除。

重置、新会话、删除与定期清理会结束绑定的 core 会话并清理待处理审批。同一逻辑会话的创建和结束串行执行；不同会话可独立初始化。

历史读取保留 response/event 回退、消息总数与来源过滤语义，仅在内存中保留请求的尾部消息和当前 JSONL 记录，并在 blocking pool 解析。当前仍扫描文件两次；单条超大记录仍可能占用较多内存，索引分页和记录大小限制属于后续工作。

路由迁移仅对输入快照中提供的行执行版本校验更新，保留计算迁移期间新建的会话。显式 `SessionStore::replace_all` API 则将调用时缓存中存在、但输入缺失的 ID 视为删除候选；仅在确实需要替换整个集合时使用。

Core 会话结束及 SSE 取消最多等待 30 秒确认关闭，以容纳 Windows 进程树清理工具的 10 秒预算和用户 shell 的 20 秒清理宽限期。定期维护最多并行结束 16 个互不相关的会话；同一逻辑会话的生命周期操作仍串行执行。
