# 执行取消与会话恢复

`savfox exec` 被 Ctrl+C 取消后，会等待主会话和子代理会话清理完毕，包括停止它们运行的子进程，然后以退出码 `130` 结束。在初始任务提交之前或核心轮次已经空闲时收到信号，同样进入清理流程。使用 `--json` 时，取消只生成一个 `turn.failed` 终态，其中 `error.message` 为 `Turn interrupted`；如果信号到达前已经交付了终态，则保留原终态，不再追加第二个。仅中断子代理不会结束主会话。

`savfox exec resume <会话ID或名称> <提示词>` 只恢复已有的会话记录。ID 或名称不存在时返回错误。`resume --last <提示词>` 在当前目录及提供商筛选条件下没有匹配会话时返回错误；`--all` 可关闭目录筛选。读取历史记录失败时会向调用方报告错误。这些失败均不会静默创建新会话；需要新会话时请使用 `savfox exec <提示词>`。

app-server 的 `turn/interrupt` 请求使用 `sessionId` 和 `turnId`，只取消指定的活动轮次。响应 `{}` 表示取消清理已完成，`turn/completed` 事件的状态为 `interrupted`。如果指定轮次已经完成、不存在或已被替代，服务端会及时返回无效请求错误（`-32600`），保留当前轮次。客户端需要处理正常完成与取消同时发生的情况。
